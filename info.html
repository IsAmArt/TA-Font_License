ข้อมูลเพิ่มเติมและบทความเกี่ยวกับฟอนต์

คู่มือการใช้งาน เทคนิคการตั้งค่า และความรู้พื้นฐานเกี่ยวกับฟอนต์ภาษาไทยจาก TA Font

บทความ: การรองรับระบบ Mark ในโปรแกรมยอดนิยมปัจจุบัน

ระบบ Mark (OpenType mark / mkmk) คืออะไร?

ฟอนต์ภาษาไทยยุคใหม่ใช้เทคโนโลยี Mark Positioning (จุดยึด Anchor) แทนการสร้างตัวอักษรสำเร็จรูป (Ligature/PUA) แบบยุคเก่า ข้อดีคือ สระและวรรณยุกต์จะจัดตำแหน่งอัตโนมัติอย่างแม่นยำ และสามารถปรับระยะห่างระหว่างตัวอักษร (Tracking / Letter Spacing) ได้โดยที่สระไม่หลุดตำแหน่ง อย่างไรก็ตาม โปรแกรมที่นำไปใช้งานต้องรองรับการประมวลผลภาษาซับซ้อน (Complex Script Shaping) ด้วย

1. โปรแกรมที่รองรับระบบ Mark ของฟอนต์ภาษาไทย

หมวดหมู่ ชื่อโปรแกรม สถานะ เงื่อนไข / การตั้งค่าเพิ่มเติม
กราฟิกและสิ่งพิมพ์ Adobe Photoshop, Illustrator, InDesign (CC ขึ้นไป) รองรับสมบูรณ์ ต้องเปิดใช้งาน World-Ready Layout (ในแผง Paragraph) หรือ World-Ready Composer ใน InDesign
กราฟิกและสิ่งพิมพ์ Figma (Web & Desktop) รองรับสมบูรณ์ รองรับอัตโนมัติทันที (ใช้เอนจิน HarfBuzz)
กราฟิกและสิ่งพิมพ์ Affinity Designer, Photo, Publisher (v2 ขึ้นไป) รองรับ ควรตั้งค่า Typography Script / Language ในแผง Character เป็น Thai เพื่อให้สระซ้อนทำงานครบ
กราฟิกและสิ่งพิมพ์ CorelDRAW (เวอร์ชันใหม่) รองรับ รองรับ OpenType Complex Script อัตโนมัติ
งานเอกสาร / ออฟฟิศ Microsoft Word, PowerPoint, Excel (2016 / 2019 / 2021 / 365) รองรับสมบูรณ์ รองรับอัตโนมัติ (Word รุ่นใหม่บังคับใช้ฟอนต์ระบบ Mark เป็นหลักและตัดการรองรับระบบ Ligature เก่าออกแล้ว)
งานเอกสาร / ออฟฟิศ Apple Pages, Keynote, Numbers (macOS / iPadOS / iOS) รองรับสมบูรณ์ รองรับอัตโนมัติผ่านระบบ Core Text ของ Apple
งานเอกสาร / ออฟฟิศ Google Docs, Slides, Sheets รองรับสมบูรณ์ รองรับอัตโนมัติผ่านเอนจินของเว็บเบราว์เซอร์
งานเอกสาร / ออฟฟิศ LibreOffice Writer, Impress รองรับสมบูรณ์ รองรับอัตโนมัติผ่านเอนจิน HarfBuzz
วาดภาพ / แท็บเล็ต Procreate (iPadOS เวอร์ชันปัจจุบัน) รองรับสมบูรณ์ รองรับผ่านระบบ Core Text ของ iPadOS
วาดภาพ / แท็บเล็ต Clip Studio Paint (เวอร์ชัน 2.0 ขึ้นไป) รองรับ รองรับการจัดตำแหน่ง Mark ภาษาไทยแล้ว (ต่างจากเวอร์ชัน 1.x เก่าที่วรรณยุกต์ลอย)
วาดภาพ / แท็บเล็ต ibisPaint X (iOS / Android) รองรับ รองรับผ่านระบบเรนเดอร์ข้อความของระบบปฏิบัติการ
ตัดต่อวิดีโอ / โมชัน Adobe Premiere Pro, After Effects (CC 2020 ขึ้นไป) รองรับสมบูรณ์ ต้องตั้งค่า Text Engine ในเมนู Preferences เป็น South Asian and Middle Eastern
ตัดต่อวิดีโอ / โมชัน Final Cut Pro, Apple Motion รองรับสมบูรณ์ รองรับอัตโนมัติผ่านระบบ Core Text
ตัดต่อวิดีโอ / โมชัน DaVinci Resolve (เฉพาะเครื่องมือ Text ปกติ) รองรับ ใช้งานได้ในเครื่องมือ Text ทั่วไปบนหน้า Edit (แต่มีปัญหาในโหมด Text+)
เว็บเบราว์เซอร์ Chrome, Edge, Safari, Firefox รองรับสมบูรณ์ แสดงผลฟอนต์เว็บ (.woff / .woff2) ระบบ Mark ได้แม่นยำ 100%

2. โปรแกรมที่ยังไม่รองรับ หรือรองรับไม่สมบูรณ์

หมวดหมู่ ชื่อโปรแกรม สถานะ อาการที่พบ / วิธีแก้ไขเบื้องต้น
ตัดต่อวิดีโอ CapCut (Mobile & Desktop) รองรับไม่สมบูรณ์ มักเกิดอาการ วรรณยุกต์ลอยหรือสระซ้อน เมื่อใส่แอนิเมชันข้อความ หรือปรับระยะห่างตัวอักษร (วิธีแก้: ตั้งค่า Character Spacing เป็น 0 เท่านั้น หรือทำข้อความเป็นไฟล์ PNG โปร่งใสมาวางแทน)
กราฟิกออนไลน์ Canva (Web & App) รองรับบางส่วน ฟอนต์ที่อัปโหลดเองบางตัวเกิดอาการสระลอย/สระจม (วิธีแก้: กดเลือกกล่องข้อความ ไปที่ Advanced settings แล้วเปิดใช้งาน Ligatures)
ตัดต่อวิดีโอ DaVinci Resolve (เฉพาะโหมด Text+ / Fusion) ไม่รองรับ เอนจินเรนเดอร์ของ Text+ ไม่รองรับการวางตำแหน่ง Mark ภาษาไทย ทำให้ สระจมหรือวรรณยุกต์ลอย (แนะนำให้สร้างข้อความเป็นไฟล์ PNG โปร่งใสจากโปรแกรมกราฟิกแทน)
เกมเอนจิน Unity (TextMeshPro ค่าเริ่มต้น) / Unreal Engine ไม่รองรับเริ่มต้น ระบบ UI พื้นฐานของเกมเอนจินมักไม่อ่านตาราง mark / mkmk ของภาษาไทย ทำให้ซับไตเติลในเกมวรรณยุกต์ลอย (นักพัฒนาเกมต้องเขียนปลั๊กอินหรือเปิดระบบ HarfBuzz เสริม)
โปรแกรม 3D Blender (3D Text Object) ไม่รองรับ ระบบพิมพ์ข้อความ 3D ไม่รองรับ Complex Script ภาษาไทย สระและวรรณยุกต์จะลอยทับกัน (วิธีแก้: พิมพ์ใน Illustrator/Inkscape แล้วแปลงเป็น Outline/SVG ก่อนนำเข้า)
โปรแกรมรุ่นเก่า Adobe CS6 หรือเก่ากว่า / Clip Studio Paint 1.x ไม่รองรับ ออกแบบมาเพื่อรองรับฟอนต์ภาษาไทยระบบ Ligature/PUA ยุคเก่า เมื่อนำฟอนต์ระบบ Mark ไปใช้จะเกิดอาการวรรณยุกต์ลอย
โปรแกรมฝังซับไตเติล โปรแกรม Burn-in Subtitle / คาราโอเกะรุ่นเก่า ไม่รองรับ โปรแกรมฝังซับรุ่นเก่าจำนวนมากใช้ตัวเรนเดอร์ข้อความพื้นฐาน ทำให้สระและวรรณยุกต์ผิดตำแหน่ง
คำแนะนำเพิ่มเติมสำหรับผู้ใช้งาน: หากนำไปใช้ในโปรแกรมตัดต่อวิดีโอที่ยังไม่รองรับระบบ Mark เต็มรูปแบบ (เช่น CapCut หรือ DaVinci Resolve โหมด Text+) แนะนำให้พิมพ์ข้อความจากโปรแกรมกราฟิกที่รองรับ (เช่น Illustrator, Photoshop, Figma) แล้วบันทึกเป็นไฟล์ PNG พื้นหลังโปร่งใส เพื่อความคมชัดและตำแหน่งสระที่ถูกต้อง 100%

ระบบ Ligature (OpenType liga / rlig / ccmp และ PUA) คืออะไร?

ระบบ Ligature คือเทคนิคการสร้างตัวอักษรสำเร็จรูปเพื่อแทนที่ชุดตัวอักษรที่พิมพ์ติดกัน (เช่น การจับคู่ ญ + ุ ให้กลายเป็น ญ ไม่มีเชิง หรือการรวมพยัญชนะ+สระ+วรรณยุกต์เป็นตัวเดียวเพื่อแก้ปัญหาสระลอยในโปรแกรมที่ไม่รองรับ mark) ซึ่งโปรแกรมส่วนใหญ่รองรับ liga ได้กว้างกว่า mark ยกเว้น Microsoft Word รุ่นใหม่ ที่ตัดการรองรับฟอนต์ไทยระบบ Ligature/PUA ยุคเก่าออกไปแล้ว

1. โปรแกรมที่รองรับระบบ Ligature

หมวดหมู่ ชื่อโปรแกรม สถานะ เงื่อนไข / การตั้งค่าเพิ่มเติม
กราฟิกและสิ่งพิมพ์ Adobe Photoshop, Illustrator, InDesign (CS5 / CS6 / CC ขึ้นไป) รองรับสมบูรณ์ เปิดใช้งาน Standard Ligatures ในแผง Character เป็นค่าเริ่มต้น (ทำงานได้ทันทีโดยไม่ต้องเปิด World-Ready Layout)
กราฟิกและสิ่งพิมพ์ Figma (Web & Desktop) รองรับสมบูรณ์ เปิดใช้งาน Ligatures อัตโนมัติ และตั้งค่าเพิ่มได้ที่เมนู Type Details
กราฟิกและสิ่งพิมพ์ Affinity Designer, Photo, Publisher รองรับสมบูรณ์ เปิดใช้งาน Standard Ligatures ในแผง Typography เป็นค่าเริ่มต้น
กราฟิกและสิ่งพิมพ์ CorelDRAW รองรับสมบูรณ์ เปิดใช้งานได้ในหน้าต่าง OpenType Features
กราฟิกออนไลน์ Canva (Web & App) รองรับ ต้องกดเลือกกล่องข้อความ ไปที่ Advanced settings > แท็บ Advanced แล้วเปิดสวิตช์ Ligatures
งานเอกสาร / ออฟฟิศ Apple Pages, Keynote, Numbers (macOS / iPadOS / iOS) รองรับสมบูรณ์ รองรับอัตโนมัติผ่านเอนจิน Core Text ของ Apple
งานเอกสาร / ออฟฟิศ LibreOffice Writer, Impress รองรับสมบูรณ์ รองรับอัตโนมัติผ่านเอนจิน HarfBuzz
งานเอกสาร / ออฟฟิศ Microsoft Word, PowerPoint (2016 / 2019 / 2021 / 365) รองรับบางส่วน รองรับเฉพาะ OpenType liga มาตรฐานเมื่อเข้าไปเปิดที่ Font > Advanced > Ligatures แต่ไม่รองรับฟอนต์ไทยระบบ Ligature/PUA รุ่นเก่า (เช่น ตระกูล PSL / JS / DSN ยุคเก่า จะเกิดอาการสระลอยหรือเพี้ยน)
วาดภาพ / แท็บเล็ต Procreate (iPadOS) รองรับสมบูรณ์ รองรับอัตโนมัติผ่านระบบ Core Text ของ iPadOS
วาดภาพ / แท็บเล็ต Clip Studio Paint (เวอร์ชัน 2.0 ขึ้นไป) รองรับ รองรับ Ligatures ตั้งแต่ v2.0 และ Contextual Alternates ใน v3.0 (ตั้งค่าใน Sub Tool Detail > Font > OpenType)
เว็บเบราว์เซอร์ Chrome, Edge, Safari, Firefox รองรับสมบูรณ์ เปิดใช้งาน liga และ ccmp เป็นค่าเริ่มต้นตามมาตรฐาน CSS

2. โปรแกรมที่ยังไม่รองรับ หรือรองรับไม่สมบูรณ์

หมวดหมู่ ชื่อโปรแกรม สถานะ อาการที่พบ / ข้อจำกัดทางเทคนิค
ตัดต่อวิดีโอ CapCut (Mobile & Desktop) ไม่รองรับ / ไม่เสถียร เอนจินเรนเดอร์ข้อความของ CapCut มักไม่อ่านตาราง GSUB (liga) และ Kerning ของฟอนต์ที่นำเข้าเอง ทำให้ตัวอักษรไม่เปลี่ยนรูปหรือสระลอย
ตัดต่อวิดีโอ DaVinci Resolve (โหมด Text+ / Fusion) ไม่รองรับ เอนจิน Text+ ไม่อ่านตาราง OpenType Ligatures (ส่วนเครื่องมือ Text ปกติบนหน้า Edit จะอ่านได้ตามระบบปฏิบัติการ)
โปรแกรม 3D Blender (3D Text Object) ไม่รองรับ ระบบพิมพ์ข้อความ 3D พื้นฐานไม่อ่านตาราง OpenType Ligatures (ต้องพิมพ์จากโปรแกรมกราฟิกแล้วแปลงเป็น SVG ก่อนนำเข้า)
เกมเอนจิน Unity (TextMeshPro ค่าเริ่มต้น) / Unreal Engine ไม่รองรับเริ่มต้น ระบบแสดงผล UI พื้นฐานไม่อ่านตาราง liga ของภาษาซับซ้อน ต้องเปิดใช้ปลั๊กอิน HarfBuzz เสริม
โปรแกรมทั่วไป โปรแกรมฝังซับไตเติล / แอปแต่งรูปมือถือทั่วไป ไม่รองรับ แอปขนาดเล็กจำนวนมากอ่านเฉพาะรหัสอักขระเดี่ยว (Unicode) โดยไม่ประมวลผลกฎการแทนที่รูปอักษร
ทำไมฟอนต์ยุคใหม่จึงเน้น mark มากกว่า ligature: ฟอนต์ระบบ Ligature ต้องสร้างตัวอักษรคู่สำเร็จรูปไว้ล่วงหน้าทุกกรณี ทำให้ไฟล์ใหญ่และมีปัญหาเมื่อผู้ใช้ปรับเพิ่มระยะห่างตัวอักษร (Tracking) เพราะสระกับพยัญชนะที่ถูกเชื่อมรวมเป็นชิ้นเดียวจะยืดห่างออกจากกันไม่ได้ ในขณะที่ฟอนต์ยุคใหม่ใช้ระบบ mark เป็นหลัก และอาจใส่กฎ liga / ccmp เสริมไว้เฉพาะจุด (เช่น ตัดเชิง ญ ฐ เมื่อเจอสระล่าง หรือแก้สระลอยใน Canva)
