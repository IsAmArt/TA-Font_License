ข้อมูลเพิ่มเติมและบทความเกี่ยวกับฟอนต์

คู่มือการใช้งาน เทคนิคการตั้งค่า และความรู้พื้นฐานเกี่ยวกับฟอนต์ภาษาไทยจาก TA Font

บทความ: การรองรับระบบ Mark ในโปรแกรมยอดนิยมปัจจุบัน

ทำความรู้จักระบบฟอนต์ภาษาไทย: ระบบ Mark vs ระบบ Ligature

1. ระบบ Mark (OpenType mark / mkmk): ฟอนต์ภาษาไทยยุคใหม่ใช้เทคโนโลยี Mark Positioning (จุดยึด Anchor) แทนการสร้างตัวอักษรสำเร็จรูปแบบเก่า ข้อดีคือ สระและวรรณยุกต์จะจัดตำแหน่งอัตโนมัติอย่างแม่นยำ และสามารถปรับระยะห่างระหว่างตัวอักษร (Tracking / Letter Spacing) ได้โดยที่สระไม่หลุดตำแหน่ง ทั้งนี้โปรแกรมที่ใช้งานต้องรองรับการประมวลผลภาษาซับซ้อน (Complex Script Shaping) ด้วย

2. ระบบ Ligature (OpenType liga / rlig / ccmp และ PUA): คือเทคนิคการสร้างตัวอักษรสำเร็จรูปเพื่อแทนที่ชุดตัวอักษรที่พิมพ์ติดกัน (เช่น การจับคู่ ญ + ุ ให้กลายเป็น ญ ไม่มีเชิง หรือการรวมพยัญชนะ+สระ+วรรณยุกต์เป็นตัวเดียวเพื่อแก้ปัญหาสระลอยในโปรแกรมที่ไม่รองรับ mark) ซึ่งโปรแกรมส่วนใหญ่รองรับ liga ได้กว้างกว่า mark ยกเว้น Microsoft Word รุ่นใหม่ ที่ตัดการรองรับฟอนต์ไทยระบบ Ligature/PUA ยุคเก่าออกไปแล้ว

ตารางเปรียบเทียบการรองรับระบบ Mark และ Ligature ของแต่ละโปรแกรม

หมวดหมู่ ชื่อโปรแกรม ระบบ Mark ระบบ Ligature เงื่อนไข / การตั้งค่าเพิ่มเติม / วิธีแก้ไข
กราฟิกและสิ่งพิมพ์ Adobe Photoshop, Illustrator, InDesign Mark: CC ขึ้นไป | Liga: CS5 / CS6 / CC+ รองรับสมบูรณ์ รองรับสมบูรณ์
Mark: ต้องเปิดใช้งาน World-Ready Layout (ในแผง Paragraph) หรือ World-Ready Composer ใน InDesign
Ligature: เปิดใช้งาน Standard Ligatures ในแผง Character เป็นค่าเริ่มต้น (ทำงานได้ทันทีโดยไม่ต้องเปิด World-Ready Layout)
กราฟิกและสิ่งพิมพ์ Figma Web & Desktop รองรับสมบูรณ์ รองรับสมบูรณ์
Mark: รองรับอัตโนมัติทันที (ใช้เอนจิน HarfBuzz)
Ligature: เปิดใช้งาน Ligatures อัตโนมัติ และตั้งค่าเพิ่มได้ที่เมนู Type Details
กราฟิกและสิ่งพิมพ์ Affinity Designer, Photo, Publisher Mark: v2 ขึ้นไป | Liga: ทุกเวอร์ชัน รองรับ รองรับสมบูรณ์
Mark: ควรตั้งค่า Typography Script / Language ในแผง Character เป็น Thai เพื่อให้สระซ้อนทำงานครบ
Ligature: เปิดใช้งาน Standard Ligatures ในแผง Typography เป็นค่าเริ่มต้น
กราฟิกและสิ่งพิมพ์ CorelDRAW เวอร์ชันใหม่ รองรับ รองรับสมบูรณ์
Mark: รองรับ OpenType Complex Script อัตโนมัติ
Ligature: เปิดใช้งานได้ในหน้าต่าง OpenType Features
กราฟิกออนไลน์ Canva Web & App รองรับบางส่วน รองรับ
อาการที่พบ: ฟอนต์ที่อัปโหลดเองบางตัวเกิดอาการสระลอย/สระจมเมื่อใช้ระบบ Mark อย่างเดียว
วิธีแก้: กดเลือกกล่องข้อความ ไปที่ Advanced settings > แท็บ Advanced แล้วเปิดสวิตช์ Ligatures
งานเอกสาร / ออฟฟิศ Microsoft Word, PowerPoint, Excel 2016 / 2019 / 2021 / 365 รองรับสมบูรณ์ รองรับบางส่วน

Ligature: รองรับเฉพาะ OpenType liga มาตรฐานเมื่อเข้าไปเปิดที่ Font > Advanced > Ligatures แต่ตัดการรองรับฟอนต์ไทยระบบ Ligature/PUA รุ่นเก่าออกไปแล้ว (เช่น ตระกูล PSL / JS / DSN ยุคเก่า จะเกิดอาการสระลอยหรือเพี้ยน)
งานเอกสาร / ออฟฟิศ Apple Pages, Keynote, Numbers macOS / iPadOS / iOS รองรับสมบูรณ์ รองรับสมบูรณ์ รองรับทั้งระบบ Mark และ Ligature อัตโนมัติผ่านเอนจิน Core Text ของ Apple

งานเอกสาร / ออฟฟิศ LibreOffice Writer, Impress Windows / macOS / Linux รองรับสมบูรณ์ รองรับสมบูรณ์ รองรับทั้งระบบ Mark และ Ligature อัตโนมัติผ่านเอนจิน HarfBuzz
วาดภาพ / แท็บเล็ต Procreate iPadOS เวอร์ชันปัจจุบัน รองรับสมบูรณ์ รองรับสมบูรณ์ รองรับทั้งระบบ Mark และ Ligature อัตโนมัติผ่านระบบ Core Text ของ iPadOS
วาดภาพ / แท็บเล็ต Clip Studio Paint เวอร์ชัน 2.0 ขึ้นไป รองรับ รองรับ
Mark: รองรับการจัดตำแหน่ง Mark ภาษาไทยแล้ว (ต่างจากเวอร์ชัน 1.x เก่าที่วรรณยุกต์ลอย)
Ligature: รองรับ Ligatures ตั้งแต่ v2.0 และ Contextual Alternates ใน v3.0 (ตั้งค่าใน Sub Tool Detail > Font > OpenType)
วาดภาพ / แท็บเล็ต ibisPaint X iOS / Android รองรับ รองรับตาม OS รองรับผ่านระบบเรนเดอร์ข้อความของระบบปฏิบัติการ (iOS / Android)
ตัดต่อวิดีโอ / โมชัน Adobe Premiere Pro, After Effects CC 2020 ขึ้นไป รองรับสมบูรณ์ รองรับสมบูรณ์ ต้องตั้งค่า Text Engine ในเมนู Preferences เป็น South Asian and Middle Eastern เพื่อให้ทั้งระบบ Mark และ OpenType Ligatures ทำงานสมบูรณ์
ตัดต่อวิดีโอ / โมชัน Final Cut Pro, Apple Motion macOS รองรับสมบูรณ์ รองรับสมบูรณ์ รองรับทั้งระบบ Mark และ Ligature อัตโนมัติผ่านระบบ Core Text ของ Apple
ตัดต่อวิดีโอ / โมชัน DaVinci Resolve (เครื่องมือ Text ปกติ) หน้า Edit รองรับ รองรับ ใช้งานได้ในเครื่องมือ Text ทั่วไปบนหน้า Edit โดยอ่านตารางฟอนต์ตามระบบปฏิบัติการ (แต่มีปัญหาในโหมด Text+)
ตัดต่อวิดีโอ / โมชัน DaVinci Resolve (โหมด Text+ / Fusion) หน้า Edit / Fusion ไม่รองรับ ไม่รองรับ

วิธีแก้: แนะนำให้สร้างข้อความเป็นไฟล์ PNG โปร่งใสจากโปรแกรมกราฟิกที่รองรับแทน
ตัดต่อวิดีโอ / โมชัน CapCut Mobile & Desktop รองรับไม่สมบูรณ์ ไม่รองรับ / ไม่เสถียร
อาการที่พบ: เอนจินเรนเดอร์มักไม่อ่านตาราง GSUB (liga), Kerning และ Mark ของฟอนต์ที่นำเข้าเองอย่างสมบูรณ์ เกิดอาการ วรรณยุกต์ลอยหรือสระซ้อน เมื่อใส่แอนิเมชันข้อความหรือปรับระยะห่างตัวอักษร
วิธีแก้: ตั้งค่า Character Spacing เป็น 0 เท่านั้น หรือทำข้อความเป็นไฟล์ PNG โปร่งใสมาวางแทน
เว็บเบราว์เซอร์ Chrome, Edge, Safari, Firefox Desktop & Mobile รองรับสมบูรณ์ รองรับสมบูรณ์ แสดงผลฟอนต์เว็บ (.woff / .woff2) ระบบ Mark ได้แม่นยำ 100% และเปิดใช้งาน liga / ccmp เป็นค่าเริ่มต้นตามมาตรฐาน CSS
เกมเอนจิน Unity / Unreal Engine TextMeshPro ค่าเริ่มต้น / UI พื้นฐาน ไม่รองรับเริ่มต้น ไม่รองรับเริ่มต้น ระบบ UI พื้นฐานของเกมเอนจินมักไม่อ่านตาราง mark / mkmk และ liga ของภาษาซับซ้อน ทำให้ซับไตเติลในเกมวรรณยุกต์ลอย (นักพัฒนาเกมต้องเขียนปลั๊กอินหรือเปิดระบบ HarfBuzz เสริม)
โปรแกรม 3D Blender 3D Text Object ไม่รองรับ ไม่รองรับ
อาการที่พบ: ระบบพิมพ์ข้อความ 3D พื้นฐานไม่รองรับ Complex Script และไม่อ่านตาราง OpenType Ligatures สระและวรรณยุกต์จะลอยทับกัน
วิธีแก้: พิมพ์ใน Illustrator / Inkscape แล้วแปลงเป็น Outline / SVG ก่อนนำเข้า
โปรแกรมรุ่นเก่า Adobe CS6 หรือเก่ากว่า / Clip Studio Paint 1.x เวอร์ชันเก่า ไม่รองรับ รองรับ (ระบบเก่า) ออกแบบมาเพื่อรองรับฟอนต์ภาษาไทยระบบ Ligature/PUA ยุคเก่า (เช่น CS6 รองรับ Standard Ligatures แต่ไม่รองรับ Thai Mark Positioning) เมื่อนำฟอนต์ระบบ Mark ไปใช้จะเกิดอาการวรรณยุกต์ลอย
โปรแกรมทั่วไป / ซับไตเติล โปรแกรม Burn-in Subtitle / คาราโอเกะรุ่นเก่า / แอปแต่งรูปมือถือทั่วไป ไม่รองรับ ไม่รองรับ โปรแกรมฝังซับรุ่นเก่าและแอปขนาดเล็กจำนวนมากอ่านเฉพาะรหัสอักขระเดี่ยว (Unicode) โดยไม่ประมวลผลตาราง mark หรือกฎการแทนที่รูปอักษร ทำให้สระและวรรณยุกต์ผิดตำแหน่ง
คำแนะนำเพิ่มเติมสำหรับผู้ใช้งาน: หากนำไปใช้ในโปรแกรมตัดต่อวิดีโอที่ยังไม่รองรับระบบ Mark เต็มรูปแบบ (เช่น CapCut หรือ DaVinci Resolve โหมด Text+) แนะนำให้พิมพ์ข้อความจากโปรแกรมกราฟิกที่รองรับ (เช่น Illustrator, Photoshop, Figma) แล้วบันทึกเป็นไฟล์ PNG พื้นหลังโปร่งใส เพื่อความคมชัดและตำแหน่งสระที่ถูกต้อง 100%
ทำไมฟอนต์ยุคใหม่จึงเน้น mark มากกว่า ligature: ฟอนต์ระบบ Ligature ต้องสร้างตัวอักษรคู่สำเร็จรูปไว้ล่วงหน้าทุกกรณี ทำให้ไฟล์ใหญ่และมีปัญหาเมื่อผู้ใช้ปรับเพิ่มระยะห่างตัวอักษร (Tracking) เพราะสระกับพยัญชนะที่ถูกเชื่อมรวมเป็นชิ้นเดียวจะยืดห่างออกจากกันไม่ได้ ในขณะที่ฟอนต์ยุคใหม่ใช้ระบบ mark เป็นหลัก และอาจใส่กฎ liga / ccmp เสริมไว้เฉพาะจุด (เช่น ตัดเชิง ญ ฐ เมื่อเจอสระล่าง หรือแก้สระลอยใน Canva)
